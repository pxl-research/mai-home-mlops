Propose an implementation plan for this:

Currently there is a data generation script in @/generator/main.py
This script will generate new time series data on the fly and stores it in a hypertable.
For the current table creation see @/database/init.sql
However, currently we only generate and store the time series data for 1 household.

The models that can be used are stored in @/generator/models.

Plan of action:
* Use @/generator/generate_training_data.py for generating the data instead of what is currently in /generator/main.py.
So put everything from generator/generate_training_data.py into generator/main.py.
* Adjust table creation and columns in init.sql accordingly and do so that this data is stored as efficiently as possible.
Also make sure that the column names match the ones in the dataframes in generate_training_data.py.
* Load the models from the @models folder at startup.
* Instead of generating data for 1 household, generate it for 6 households with the following characteristics:
  * household_id: single_be, single_nl, couple_be, couple_nl, family_be, family_nl
    You can see a full example in @/generator/inference_example.py.
* At startup first check if there is data in the database, if not put for 6 households hourly data in the database starting from 2024-01-01 00:00:00 until the last passed hour of the current time. This makes sure the database has initial data to start from.
Also make sure that for each hour there is a water leak detection. Do this based on the example in inference_example.py and use Python for this, do NOT put it in init.sql!
* Fill gaps when the last datapoint per household stored in the database is not matching the last hour passsed.
e.g.: if the current time is now 17:30 the last datapoint per household stored in the database should be 17:00 today.
So instead of generating a current datapoint, all the missing datapoints in between will be added as well.
* New data should be generated each hour of the day for each of the 6 households.
* When generating the 6 households, vary the has_leakage_prob a bit but make it consistent for each household.
One household should have 0.0, another 0.5, another 0.4, another 0.3, another 0.2, another 0.1.
* Update the Grafana dashboard implementation in `@/dashboard` to accommodate multi-household time series data and display water leak detection status:
1. **Multi-Household Support:**
   - Instead of displaying a single graph, update the dashboard to visualize water consumption over time for all 6 households: `single_be`, `single_nl`, `couple_be`, `couple_nl`, `family_be`, and `family_nl`.
   - Provide a way to either view all 6 households side-by-side / stacked, or allow filtering/switching between specific households via a selector control.

2. **Leak Detection Overlay:**
   - For each household's time series chart, overlay the water leak detection status (binary values: `0` for no leakage, `1` for leakage).
   - Use a contrasting color or distinct visual element (e.g., a secondary y-axis line, shaded background regions/bars, or distinct markers) so the leak events (0 vs. 1) are immediately distinguishable from the continuous water consumption curve.

3. **Data Fetching Adjustments:**
   - Update API calls/queries fetching data from the database to query by `household_id` and include both consumption metrics and the `has_leakage` status columns.
